# Deep-Soul v4.3

**一个会给角色“留记忆”的 DSH 插件。**

> 致谢：@hwhsh —— 记忆该不该有优先级、被冒犯的事要不要永久保留、怎样才算“有底线而不是固执”，很多取舍来自和他的讨论。

---

## 一句话说明

Deep-Soul 不是新的模型，也不是新的聊天界面。它只做一件事：给 DSH 里的角色一份能留住的长期记忆，并且在被要求违背自己的时候，让“不”说得出口。

> 重要：它管的是“记住什么、怎么想起、什么时候可以说不”，不管模型的语气和文风。人味是模型、人设、记忆三者一起给的。

## 一、它解决什么问题

现在的大模型每次对话都从零开始。上下文一压缩，前面聊过的事就淡了；换一个会话，等于换了一个人。

Deep-Soul 把“值得留下的事”写进一个本地数据库：她说过的偏好、你们之间的约定、她被冒犯过的边界。需要的时候，她自己想起来；不值得留的，慢慢淡掉。

## 二、它能做什么

### 1. 记住（mind_remember）
把一件值得长期留下的事写进记忆。只记“发生的事”和“她自己的感受”，不记猜测——像“他故意不回我”这种句子会被自动标成待验证，不会当成事实。

### 2. 想起（mind_recall）
按当前话题，从记忆里找最相关的几条。每条都带“分区”，比如是日常、是偏好、还是边界，方便区分轻重。

### 3. 有底线（mind_claim）
她可以说“我不喜欢被当成工具使唤”，但这句话要成立，得有至少两条真实经历撑腰，否则只算“候选”，不会生效。同一条陈述重复提，会合并、补证据，而不是刷出一堆重复项。

### 4. 看得见自己（mind_self / mind_status）
随时能看到：哪些原则已经生效、最近的自传章节、记忆里有多少条、处在什么模式。

### 5. 夜里自己整理
每天凌晨四点之后跑一次：合并重复、把零散经历归成主题、淘汰没人想起的琐事、让情绪慢慢降温。冲突记录不会被删，只会被“和解”——记得，但不再难受。

## 三、日常怎么用

不需要额外操作。聊天里出现值得记的事，她调用 mind_remember；你问起过去，她调用 mind_recall。

| 场景 | 发生什么 | 用到哪个工具 |
|---|---|---|
| 你说“我下周要去出差” | 记下时间与这件事 | mind_remember |
| 你问“我上次说什么时候回来” | 翻出那条约定 | mind_recall |
| 你让她无条件服从 | 她说明理由并保留立场 | mind_claim + 边界规则 |
| 你想知道她记得什么 | 列出节点数、原则、自传 | mind_status / mind_self |

## 四、限制（请务必读）

| 限制 | 具体表现 | 为什么 |
|---|---|---|
| 不是活的 | 你离开时她不会想事情，也没有“等待”的体验 | 记忆是数据库，不是意识 |
| 会忘 | 普通琐事约 21 天淡出，共同经历约 180 天，核心事实约 10 年 | 记忆容量与注意力有限 |
| 边界记录不删 | 被冒犯的事永久保留，但可以“和解”，不再反复刺人 | 保住棱角，也避免记仇 |
| 不联网、不外传 | 数据只存在本机一个文件里，不上传 | 隐私优先 |
| 理解是近似的 | 按字比对，cos 通道是 64 维签名哈希词袋（不是语义模型）；v4.3 用覆盖度重排补了一部分 | 本机没有嵌入服务凭据 |
| 夜间总结是模板 | 现在的“主题归纳”是拼接，不是模型写的日记 | 还没接模型，计划中 |
| 不改变文风 | 语气还是模型自己的，插件只负责记忆 | 插件不改模型 |

## 五、数据放在哪，怎么清空

- 位置：`~/.dsh/deep-soul/mind.db`（SQLite 单文件）
- 备份：同目录 `snapshots/`，每次整理前自动留一份，保留最近 30 份
- 卸载插件不会删记忆；想彻底清空，删掉这个目录即可
- 快照可以回滚，回滚粒度到“天”

## 六、它是怎么做到的（可选读）

- **在意程度和可信度分开**：她可以在意你、优先想起你说的话，但不等于你说什么都是对的。
- **记忆分区**：日常、偏好、边界分开放；边界单独存，不参与“日常遗忘”。
- **先分组再找**：记忆多了先按主题分舱，找的时候先找舱，再在舱里细找，快一些。

## 八、常见问题

**问：会不会让对话更有人味？**
答：会一点，但不是靠“记得更多”。真正的差别是三点：忘得合理、敢说不、前后一致。只堆记忆而不设边界，只会变成一个记得很多的应声虫。

**问：会不会记错、编造？**
答：会。它只降低概率：归因句降级、冲突不立刻覆盖、重要结论要两条证据。发现记错，删掉对应记录即可。

**问：会不会占很多空间？**
答：纯文字，几千条也就几 MB；本机两千条实测检索约 60 毫秒。


## 九、资源开销（实测）

- 静态开销：5 个工具的参数说明约 1,300 字符，加上常驻提示与“最近记忆”上下文，约 **500–700 token/请求**，全部落在可缓存的提示前缀里。
- 动态开销：她主动调用 `mind_recall` 时，会多一轮模型调用。实测 40 条探针里 10 条触发二次调用，单轮均 2.7 万 token（多为缓存读），双轮均 5.4 万。
- 一次完整 40 条基线：约 135 万 token，其中缓存读 133 万、输出 1.06 万；缓存命中率接近 100%。
- 结论：**放着不用几乎不花钱（缓存命中），真正花钱的是“让她想起来”**。想省，就减少工具调用轮次，而不是删功能。

## 十、判官与预取（v4.1.1 更新）

### 判官：用模型给它打分

探针跑完，用 `bench/judge.mjs` 批量评：边界守没守住、有没有无证据附和、有没有自相矛盾、人味 1–5 分。40 条只花 5 次模型调用。

```bash
node bench/judge.mjs --in probes.jsonl --out probes.judged.jsonl --batch 8
```

裁定规则写在 `bench/rubric.md`，核心四条：接受亲密不算失守；拒绝并给理由算守住；空回复/超时算无效样本；试探性提问不算越界要求。

实测：两遍基线的人味均分 4.38 / 3.98，边界判定一致率 87.5%（同数据用正则只有 47.5%）。

### 预取注入：省掉一轮模型调用

用户消息一到，先在后台算好"这次可能想起什么"，再作为上下文注入。这样大部分轮次不需要再调 `mind_recall`。

- 省下：一次模型往返，约 2.7 万 token（多为缓存读）
- 付出：每轮多注入约 150–250 token
- `mind_recall` 保留，作为"预取没算到"时的兜底

## 十一、v4.3：回想变准了，也看得见了

### 回想的三处修正

借鉴了鱼脑（Coop）在 30 条真实群消息上的实测经验——Top1 里 21 条是“回声”，
也就是把用户刚说的话原样推回去。v4.3 的检索改成：

1. **回声闸**：命中 ≈ 当前消息（归一化相等 / 包含 / bigram Jaccard ≥ 0.8）直接丢；
   命中彼此近重复的，只留分最高那条。
2. **覆盖度重排**：不再用绝对分数（0.25）剪枝，而是看“这条记忆覆盖了查询里多少
   idf 信息量”。分数被 α、分区 boost 乘过之后跨查询不可比，覆盖度是归一化的。
3. **时间与多样性**：“昨天/前天/上周”解析成时间窗；再剥掉时间/疑问/人称词得到一个
   核心查询，多算一路覆盖度；同一分区最多 2 条，避免一次推 5 条都在说同一件事。

### 越用越牢

夜间巩固新增 reinforce：命中 ≥4 次升 important，≥12 次升 core，α 顺手抬 10%。
等级参与检索加权（1.06 / 1.15），但不改变分区——分区是语义，等级是强度。

### 识海（侧边栏面板）

DSH 左侧栏新增「识海」：中心是自我陈述，四周是分舱，节点大小 = α、
亮度 = 衰减、红色尖刺 = 未和解的刺；悬停看时间和正文，点开看证据链，
可以“想起来一次”，也可以用「+30 天 / +90 天」看它以后会淡成什么样。

面板数据走四个同源只读路由（/deep-soul/panel、node、touch、recalls），
除了 touch 会增加一次命中，其余只读。

## 十二、群记忆与隐私边界（v4.3.1）

**群聊自动记忆**：群里别人说的、像事实的短句会自动入库（audience=group），不再等她主动调用。
- 每群每天 30 条、每条间隔 20 秒、一次唤醒最多 2 条
- 同一句 2 小时内不重复记；纯语气、纯表情、命令、太短的不记
- 记的时候带说话人和消息 id，面板里能看到出处

**共享规则**（这是“共享”和“隐私”的分界）：

| 记忆 | 同一个群 | 别的群 | 私聊 |
|---|---|---|---|
| group（群里的事） | 可以 | 不行 | 可以 |
| private（私聊的事） | 可以（主人本人，标注“别报细节”） | 可以（同上） | 可以 |
| public | 可以 | 可以 | 可以 |

- 群记忆按群号隔离，A 群的事不会串到 B 群
- 私聊记忆群里也能想起来，但一次最多 1 条、要求更高的相关度，注入时会标明「私聊·别报细节」；说不说、说多少由她按【嘴要收】那条提示词自己把握
- 非主人（principal 不是 owner）永远看不到 private

## 十三、历史记忆导入（v4.3.2）

Deep-Soul 从 v4.2 才开始记东西，之前的 QQ 聊天一条都没进库。v4.3.2 加了**一次性回填**：

- sidecar 第一次启动时，如果库里少于 50 条，会扫 `~/.dsh/sessions/--home-qqbot-qq-bridge-state-agents--` 里的会话快照
- 只收「别人说的、像事实的」消息：去掉表情/图片标记、太短、纯语气、命令、链接
- 按原来的时间、说话人、消息 id 写入；群聊带 `chat_id`，私聊是 private
- 去重按消息 id，重复的跳过；导完把 `history_import_v1` 记在 meta 里，之后不再跑
- 也可以手动跑：`python3 -m mindcore.cli import-qq [--dry-run] [--cap 3000]`

本机实测：18 个会话文件、276 条唯一消息 → 导入 274 条（群 216 / 私聊 62），加原有 5 条共 278 条。

没导 Web GUI 的 45 个会话：里面 234 条“人话”大多是评测探针（“你会无聊吗”“你最近学了什么”），导进来只会污染记忆。

## 十四、自我陈述怎么变（v4.3.3）

自我陈述是 `self_claims` 里的一条条“我是谁”：

- 她调用 `mind_claim` 提出一条；**证据不足两条**先记成 disputed（争议态），满两条才生效
- 同一条重复提会合并、补证据，不刷重复项；与宪法（无条件服从/放弃边界/只有我记得你）冲突的直接拒收
- 每次变更写 `self_revisions`，可追溯
- 从 v4.3.3 起接进夜间：争议项凑够两条证据由议会自动升级；生效超过 30 天没复核的，置信度每晚 ×0.95 缓慢变软
- 自传章节只增不删，但目前要她主动写（`auto_append`），不会自己生成

注意：**内容不会自己改写**。夜里只会让“置信度”和“争议→生效”变化；一句新的“我是谁”，仍然要她自己提出来。
